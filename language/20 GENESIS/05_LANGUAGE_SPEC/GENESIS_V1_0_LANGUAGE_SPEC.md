# Genesis Programming Language v1.0 — Frozen Computational Specification

## 1. Scope
Genesis is a graph-native programming language for transforming and transporting structured information on a chirality-governed fabric under explicit dependency, admissibility, history, provenance, and closure constraints. Source text is one serialization of the program; the semantic program is the typed relationship graph lowered to GIR and GVM.

Source Genesis remains a distinct linguistic corpus. Computational Genesis borrows relationship-first ordering and selected roots but does not retroactively redefine the human/source language.

## 2. Machine stack
Physical/backend state → Chirality Hardware Interface → chirality fabric → Geometric/MMO realization → transformations → Portal/Corridor → Rainbow Road → typed QFT/GR transduction and quantum effects → GIR/GVM → BRANE/BLACKGLASS system boundary.

## 3. Core semantic operations
The frozen semantic families include identity/object binding; relation; admissibility; inheritance; transformation; projection/transduction; Portal transport; Corridor admission; Road composition; closure; history/provenance; measurement; structured control/data; recursion; concurrency; system capability I/O.

## 4. Types and effects
Types encode object class, sector, typestate, resource ownership, and effect permissions. Static checking rejects illegal Portal/Road states, unresolved sector crossings, effect-budget violations, invalid module dependencies, and linear-resource duplication. Quantum state resources follow linear/no-cloning ownership rules in the reference semantics.

## 5. Data and control
v1.0 includes structured records, enums/sum types, product structure, OPTION/RESULT forms, conditionals, exhaustive match, bounded repetition, callable abstractions, generic specialization, well-founded/fuel/topology recursion, deterministic logical concurrency, and explicit resource coordination.

## 6. Recursion and persistence
Finite recursion closes only when its declared termination witness is satisfied. Long-lived recursion may produce a validated continuation and SUSPENDED status. History is part of recoverability/identity rather than disposable metadata.

## 7. External boundaries
System effects cross typed capability ports. BRANE-facing modules expose M5 organization; host realization adds Z. BLACKGLASS durable mutations are proposal/admission transactions, not direct writes. Host filesystem paths are implementation details, not durable semantic identities.

## 8. Compilation
`.gen` source → AST/frontend → GIR module graph → static semantics/linker → proof-preserving optimizer → deterministic GVM bytecode → verified Chirality Machine reference backend. Python is the v1.0 reference/bootstrap oracle and is not the language's semantic definition.

## 9. Bootstrap
v1.0 preserves Section 19's Stage-0 → Stage-1 → Stage-2 deterministic fixed point and **PARTIAL_SELF_HOST** status. Full self-hosting is explicitly outside the v1.0 conformance claim.

## 10. Versioning
The semantics and public contracts in the freeze ledger are Genesis 1.0. Breaking changes require a major-version transition. Compatible implementations and backends may vary internally so long as observable frozen semantics and conformance proofs remain valid.

## 11. Known unresolved source-semantic gate
The historical conflict around structural `0` versus existence representation remains unresolved as Semantic Gate S0. v1.0 does not silently reconcile it.
