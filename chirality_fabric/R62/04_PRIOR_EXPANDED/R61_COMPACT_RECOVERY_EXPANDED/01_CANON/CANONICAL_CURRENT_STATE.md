## 7. Multiscale update result

A local tile color change definitely changes:

- the complete seed configuration;
- every incident relationship involving that tile;
- potentially the set of future updates available to neighboring tiles.

It does **not yet prove** that the neighboring tile must immediately change color.

For an Orange/Green seed following one Orange-to-Blue path:

`(O,G) -> (Y,G) -> (G,G) -> (B,G)`.

The seed-level readout is:

`Y -> Y -> G -> G`.

Therefore the underlying configuration may update multiple times before a larger-domain readout changes.

At byte level, four occupied tile phases give a provisional constrained state space inside `(S1)^4`.

At block level, 32 occupied tile phases give a provisional constrained state space inside `(S1)^32`.

These are configuration-space descriptions, not claims of additional physical dimensions.

A block-level Red-to-Green update is therefore a coordinated path of lower-level tile updates followed by seed, byte/bite, and block re-resolution—not a primitive repainting of the block.
