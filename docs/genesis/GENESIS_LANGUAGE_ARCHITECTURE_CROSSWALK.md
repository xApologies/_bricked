# Genesis Language + Trinity Crosswalk

The existing Genesis Language is preserved.

Frontend already provides:
.gen -> typed AST -> semantic lowering -> GIR-MODULE -> checker/linker -> GVM.

Relationship-first roots already align:
en = bind identity/result; rel = relationship; ve = Portal-mediated transport;
ar = inheritance; tor = Portal closure.

Working crosswalk:
GEOMETRIC -> State/native semantic object.
rel -> Shell relationship construction.
portal -> Rainbow Road request.
ve -> Road transport.
tor -> Portal closure/receipt.
capability declaration -> software request/declaration of authority.
capability enforcement -> Road/Nexus/Guardian boundary.
GIR -> candidate computational projection of Shell semantic geometry.
GVM/bytecode/registers -> reference/host realization unless separately proven native.
BRANE M5/B6 -> donor/request-relative realization, not automatically R5/H6.

Git's no-hidden-CPU rule controls: registers, stack frames, LOAD/STORE and binary
arithmetic may be lowering targets without becoming Genesis ontology.

Engineering Trinity:
Hardware = realizes Genesis.
Software = expresses Genesis.
Guardian = governs/manages Genesis.

Do not confuse this with the Mathematics/Semantic Language/Programming Language
authority grouping or Trinity 3.0 donor coordinates.

The Trinity cuts across State, Nexus, Shell, Sea and Rainbow Road rather than mapping
one-to-one to domains.

Status: WORKING crosswalk; GIR/Shell identification is CANDIDATE.
